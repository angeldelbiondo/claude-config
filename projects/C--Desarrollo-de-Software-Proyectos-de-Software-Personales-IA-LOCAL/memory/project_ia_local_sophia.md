## What Sophia is
A local AI agent Angel is building on his own hardware (Windows 11, i9-13900HX, RTX 4070 Laptop 8GB VRAM, 32GB RAM), started 2026-06-30. No voice (explicitly cut).

**Course decision 2026-07-06 (Angel was stuck/overwhelmed and delegated the call):** Sophia's home is `sophia_chat.py`, a Python backend (`http.server`, stdlib-only, talks to Ollama) serving an embedded HTML/CSS/JS frontend, grown incrementally. v0.2 has persistent conversations (`conversations/`), 4 sandboxed tools (list/read project files, write only inside `workspace/`, datetime), agent loop with tool chips in UI, `think:false` for qwen3 speed. Default model `qwen3:8b` (only one with reliable tool-calling — qwen2.5-coder emits tool calls as loose text, confirmed broken with both Goose and raw API expectations). All verified with real end-to-end tests.

**Paused, not dead:** Goose (works, confirmed e2e, not Sophia's interface), Agent-S (installed, never live-tested), browser-use (works — best config confirmed 2026-07-06: `qwen3-vl:4b` at 100% GPU, 4m30s/task and judge-passed, vs 11m36s for vl:8b; vision OFF fails — text-only qwen3:8b got lost in 18 steps), DeepSeek API (researched, viable at $0.14/M input, parked — only relevant if live-speed browser agent ever needed). Rule: big pieces come back only when the chat falls short for something concrete.

## Filosofía de dependencias — REVERTIDA 2026-07-12
Angel explícitamente rechazó el principio "un solo archivo, sin dependencias externas" que veníamos aplicando — dijo que es "todo lo contrario" a lo que quiere. **Regla nueva:** investigar en profundidad (WebSearch, múltiples fuentes), combinar las mejores piezas públicas disponibles ("como Lego") en vez de encasillarse en una sola solución o evitar dependencias por dogma. El backend Python sigue siendo stdlib-only (eso no cambió, es una decisión distinta), pero el frontend ahora usa librerías externas libremente — vendorizadas localmente (descargadas una vez, servidas por el propio server, cero llamadas a internet en runtime) para mantener el espíritu 100%-local/sin-nube, que ese sí sigue vigente. **Cómo aplicar:** ante cualquier pedido de feature nueva, primero investigar qué ya existe públicamente y de qué se puede componer, no reinventar ni asumir que hay que escribirlo todo a mano.

## Dirección de UI/producto
Angel quiere que Sophia se sienta "viva" visualmente, no solo funcional — busca inspiración en estéticas de asistentes de IA pop-culture (Jarvis) que ve circulando en redes (TikTok). El home real de la interfaz es un orb de partículas reactivo, grande (`min(60vmin,620px)`), que reacciona al mouse (parallax + abombamiento hacia el cursor) y al estado de la conversación (idle/pensando/revelado al llegar texto) — no a voz, Sophia no tiene voz. Construido en v0.6 con **OGL** (no Three.js — se migró de Three.js a OGL en v0.6 por ser ~4.5x más liviano) y shaders GLSL propios (ruido simplex + glow), técnica tomada de aguscruiz/voiceorb (MIT) + tutorial de Codrops sobre partículas interactivas. Sidebar y HUD de sistema están ocultos por default, aparecen con hover (manija en el borde izquierdo / ícono en el header) — el minimalismo real significa "mostrar solo lo que se está usando", no solo estética limpia con todo visible. **Cómo aplicar:** cuando Angel traiga una referencia visual de redes sociales, el patrón es investigar la referencia real (a veces la fuente exacta no existe o está mal identificada — no perder tiempo persiguiéndola) y priorizar replicar el efecto/sensación combinando varias fuentes, no encontrar un único repo que lo tenga todo.
